# Проверка RubUP Automation 4.0

23 октября 2026 года. Linux x86-64, Python 3.12.14, PySide6 6.12.0,
Playwright 1.64.1, системный Chromium 154.0.8037.57.

## Автоматические проверки

- Полный набор: **494 теста**, включая все **407 неизменённых тестов 2.0/3.0**.
  Прежние исходники генерации и интерфейса сохранены в `legacy_v3`; только pytest
  добавляет архив к путям импорта. Рабочая точка входа 4.0 архив не загружает.
- Проверен сценарий 50 видео / 100 разных назначений без обращений к ИИ,
  публикаций, лайков или отправок Telegram. Очереди двух аккаунтов независимы.
- Банк: до 500 строк, обязательный RubUP, нормализация дубликатов, случайное
  атомарное назначение, конкурентные соединения, нехватка текстов и безопасный
  сброс использования с сохранением незавершённых назначений.
- Playwright: настоящие локальные HTML-страницы с textarea и contenteditable,
  сохранение и изоляция двух профилей, ручной вход, повтор после открытия поля,
  отмена, проверка ID видео и точного текста после вставки. Усечённый текст
  не получает отметку об успешном заполнении. Кнопки публикации и лайков не нажимаются.
- Отдельные ручные подтверждения вставки, публикации и лайка; восстановление
  после перезапуска; остановка до запуска рабочего потока; безопасное закрытие
  во время обработки и создания демонстрации. Qt запускается в режиме offscreen.
- Telegram проверен HTTP-моками: только URL, только после выполнения обоих
  аккаунтов, сохранение исторического журнала, SENT без повторов, UNKNOWN и
  незавершённая резервировка после сбоя без автоматической повторной отправки.
- Миграция добавляет `v4_*` таблицы и собственный маркер версии 4, сохраняя
  прежние таблицы и `PRAGMA user_version=1`. До миграции создаётся согласованная
  SQLite-копия. Ошибка резервного копирования прерывает обновление.
- Сравнение с резервной копией подтвердило побайтовую сохранность исходных
  настроек и изображений и сохранность каждой строки всех прежних таблиц SQLite.
  Ранее опубликованные видео не создают новых заданий и не расходуют банк.
- `pip check`, компиляция модулей, `git diff --check`, CLI `--batch-demo`
  и `--gui-smoke` выполнены успешно.
- ZIP проверяется на целостность и SHA-256 каждого исходника. Включён чистый
  шаблон 4.0; рабочие настройки, `.env`, DPAPI, базы, логи, сессии, окружение
  Python и вложенные ZIP не упаковываются. Сценарии BAT сохраняют UTF-8/CRLF.

## Границы проверки

- В этой облачной среде загрузка комплектного Chromium с `cdn.playwright.dev`
  отклонена прокси: HTTP 403 `Domain forbidden`. Для браузерных тестов явно выбран
  установленный системный Chromium. Рабочая программа Windows использует обычный
  Chromium Playwright, устанавливаемый через `install.bat`.
- Windows 10/11, нативный DPAPI, PowerShell и сборка EXE здесь не запускались.
  Сценарии установки и сборки проверены по содержимому; DPAPI — тестовым адаптером.
  ZIP содержит исходники и сценарии, а не проверенный на Windows готовый EXE.
- Настоящие аккаунты TikTok и Telegram не использовались. Текущая разметка
  TikTok, ручная авторизация и доставка в настоящий чат требуют проверки на ПК.
  При изменении поля предусмотрены понятная ошибка и ручная вставка.
- Локальные подтверждения отражают действия пользователя; программа не выдаёт
  их за независимую проверку публикации или лайка на стороне TikTok.

Версия перед обновлением сохранена в `backup-v3`, версия 2.0 — в `backup-v2`.
Разработка и архив 4.0 находятся в `rubup-v4`. Протокол прежней проверки:
[validation-v2.md](validation-v2.md).
