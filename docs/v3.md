# RubUP Automation 3.0

Обновление существующего проекта: пакетная подготовка 1–100 TikTok-ссылок и два
независимых аккаунта. Для 50 подходящих новых видео можно подготовить до 100 разных
комментариев. Реальная публикация, изображение и лайк выполняются человеком.

## Сохранение предыдущей версии

- `backup-v2` содержит версию 2.0 на коммите `1ed4d5b34a6db557f879bfee0a240259abdb67d6`.
- Разработка 3.0 находится в `rubup-v3`; `main` остаётся на 2.0.
- Перед изменениями создана локальная резервная копия данных вне репозитория.
- Перед добавлением таблиц 3.0 создаётся согласованная резервная копия SQLite
  в `backups` рядом с рабочей базой. При ошибке копирования миграция блокируется.
- Старые таблицы, комментарии и их аккаунты не удаляются и не переназначаются.
  В слоте №1 сохраняется прежний ID аккаунта, слот №2 получает постоянный отдельный ID.

Чтобы обновиться, закройте программу, сохраните защищённую копию `data`, `images`,
`config.yaml` и `.env`, затем перенесите новые исходники в рабочую папку. Не заменяйте
ваши конфигурацию, базу или файлы ключей шаблонами из ZIP. Выполните `install.bat`
для обновления зависимостей и продолжайте запускать `start.bat`.

Для отката используйте отдельную папку с кодом `backup-v2` и копией прежних данных.
Не удаляйте версию 3.0 вместе с новыми результатами и не подменяйте открытую базу.

## Что изменилось

Пять разделов: Главная, Очередь, Аккаунты, Настройки, Помощь. На Главной — поле
списка и кнопка «НАЧАТЬ ПОДГОТОВКУ», предварительная стоимость, четыре показателя
и управление паузой/остановкой. Импорт сохраняется до сетевой подготовки, поэтому
после перезапуска ссылки не нужно вставлять повторно.

У одного видео два отдельных задания, привязанных к стабильным ID аккаунтов.
Готовый комментарий повторно не оплачивается без необходимости; подтверждённая пара
не получает второй оплачиваемый комментарий. Ошибка одного аккаунта не стирает
результат второго. Тексты проверяются на RubUP, рекламную маркировку, дубликаты
и слишком похожие формулировки относительно сохранённой истории.

Профиль браузера открывается только явным действием пользователя. Для Chrome/Edge
используется обычный аргумент `--profile-directory`; пароли, cookies и токены TikTok
не читаются. Программа не объявляет аккаунт авторизованным без подтверждённой проверки.

Публикация и обязательный лайк подтверждаются отдельно. По умолчанию ссылка ставится
в очередь Telegram после выполнения требований обоими аккаунтами. URL отправляется
один раз, без дополнительного текста. Неизвестный результат доставки блокирует
автоматический повтор. Принятие отчёта и начисление денег остаются отдельными событиями.

## Расходы и демонстрация

Лимит USD для партии хранится вместе с её состоянием. При включённом лимите и
неизвестном тарифе запросы не запускаются. Перед запросом резервируется консервативная
оценка по UTF-8-байтам инструкций/контекста, запасу и максимуму выходных токенов.
После ответа используется фактический `usage`; неизвестная оплата не считается нулевой.
Повторные варианты также учитываются. Прогноз не заменяет счёт OpenAI.

Бесплатный пример — 50 явно тестовых видео и 100 черновиков в отдельной базе
`data/batch_demo.sqlite3`. Он не выполняет платные запросы, сообщения, реальные
публикации, лайки или подтверждение вознаграждения. Рабочие данные не изменяются.

## Дистрибутив Windows

`RubUP-Automation-3.0-Windows.zip` содержит исходники и сценарии Windows, без `.env`,
зашифрованных ключей, пользовательской базы, картинок, логов, резервных копий и
вложенных старых ZIP. Проверенные исходники сопровождаются `SHA256SUMS.txt`.

`install.bat` выполняется один раз, `start.bat` запускает программу без постоянной
консоли. `build_windows.ps1` создаёт EXE без консоли в новой папке выпуска, не поверх
установленной программы с пользовательскими данными. На Linux Windows EXE и нативный
DPAPI не проверяются; сценарий сборки выполняется на Windows 10/11.

Итоговые команды и фактические результаты проверки приводятся в [validation.md](validation.md).
