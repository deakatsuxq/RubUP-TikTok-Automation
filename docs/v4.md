# RubUP Automation 4.0

Обновление существующего проекта для Windows 10/11. Основной интерфейс PySide6
использует пользовательский банк комментариев и Playwright Chromium. Генерация ИИ,
настройки OpenAI, модель и расчёт расходов в сценарии 4.0 отсутствуют.

## Рабочий сценарий

1. Добавьте до 500 собственных комментариев, каждый с новой строки. В каждом нужен RubUP.
2. Откройте официальный TikTok отдельно для первого и второго аккаунта и войдите вручную.
3. Вставьте до 100 URL и нажмите «СТАРТ». Для 50 новых видео нужно 100 свободных текстов.
4. Playwright открывает ролик в выбранном профиле и заполняет поле одним назначенным текстом.
5. Опубликуйте текст в браузере и подтвердите публикацию в приложении.
6. Поставьте лайк своему комментарию в браузере и подтвердите лайк в приложении.
7. Завершите задания обоих аккаунтов; включённый Telegram получает только URL ролика.

Открытие страницы и заполнение поля не считаются публикацией. Подтверждения фиксируют
решение пользователя; приложение не обещает независимую проверку комментария в TikTok.
Поле может быть недоступно из-за входа, CAPTCHA, отключённых комментариев или изменения
вёрстки. Программа сообщает об этом и позволяет повторить действие после ручной проверки.
Автоматической публикации, лайков, обхода CAPTCHA или имитации авторизации нет.

При изменении разметки можно вставить назначенный текст самостоятельно и отдельно
подтвердить ручную вставку. Это не заменяет подтверждения публикации и лайка.
После заполнения Playwright проверяет фактический текст поля: сокращённый или
изменённый сайтом текст не получает отметку об успешном заполнении.

## Хранение и восстановление

`automation_store.py` добавляет отдельные таблицы 4.0 к существующему хранилищу SQLite.
Миграция создаёт согласованную копию базы перед изменением схемы. Данные 2.0/3.0 и
настройки сохраняются. Состояние очереди, назначения, выбранные профили и ручные
подтверждения записываются на диск; перезапуск не выбирает новые тексты для старых задач.

Два постоянных профиля Playwright хранятся в `data/playwright_profiles/account-1`
и `account-2`. Chromium сохраняет свои cookies и сессию обычным способом; приложение
не просит пароль и не переносит существующие Chrome/Edge-профили. Все обращения к
Playwright выполняются на принадлежащем ему потоке. Папки профилей считаются личными
данными и исключены из Git, сборки и ZIP.

Пары профиль/видео уникальны. Комментарии нормализуются для исключения дубликатов,
распределяются случайно в атомарной операции; назначения сохраняются между запусками.
История не сбрасывается при сетевой ошибке. Явный сброс разрешает последующее
использование текстов завершённых задач на других видео; незавершённые назначения
и запрет одинакового текста для двух аккаунтов одного ролика сохраняются.

Пауза и остановка прекращают дальнейшие переходы и подготовку. Они не удаляют
историю и не отменяют уже совершённые пользователем действия в браузере.

Видео, у которых в прежней истории уже есть PUBLISHED, пропускаются с сообщением.
Это предотвращает повторную подготовку публикации при смене версии и не расходует
банк комментариев. Старые черновики не выдаются за публикации.

## Telegram

Доставка разрешена только после публикации и лайка комментария **обоими аккаунтами**.
Используется прежний журнал доставки, поэтому URL, отправленный старой версией,
не должен отправляться повторно. Неопределённый ответ сети получает состояние UNKNOWN:
автоматический повтор блокируется, пользователь проверяет чат вручную.

Токен и Chat ID настраиваются в приложении. На Windows используется DPAPI текущего
пользователя. Приложение не перезаписывает посторонние настройки подключения.
В логах не должно быть токенов, cookies, паролей или полного тела ошибочного ответа.

## Windows и архив

`install.bat` вызывает `setup_windows.ps1`: Python 3.12 → локальная `.venv` →
зависимости → `python -m playwright install chromium`. `start.bat` запускает GUI
через `pythonw.exe`. Первая установка требует Интернет и достаточно места для Chromium.

`build_windows.ps1` создаёт отдельную папку выпуска через PyInstaller `--onedir`
и `--windowed --collect-all playwright`. На компьютере получателя запускается
`install_chromium.bat`: для EXE он использует комплектный Node-драйвер, без Python.
Chromium находится в стандартном кэше Playwright текущего пользователя, а сессии —
в папке данных самого приложения. Это разные каталоги.

Сборщик ZIP читает `VERSION` и создаёт `RubUP-Automation-4.0-Windows.zip`.
Включает исходники, исторический архив для регрессионных тестов, статические
локальные HTML-фикстуры, инструкции и контрольные суммы. Исключает рабочие базы,
ключи, браузерные профили, логи, окружение, пользовательские картинки и вложенные ZIP.

## Совместимость и границы проверки

Предыдущие версии сохранены в ветках `backup-v2` и `backup-v3`. Изолированный
`legacy_v3` нужен сохранённым тестам старого поведения; рабочая 4.0 его не импортирует.
Его генератор и API-настройки не являются функциями новой программы и не попадают
в EXE через рабочую точку входа. Старые документы и снимки экрана помечены версиями.

Браузерные тесты используют локальные HTML-страницы: заполнение textarea и
contenteditable, отсутствие отправки, независимость профилей и сохранение сессии.
Другие тесты проверяют SQLite, уникальность назначений, восстановление очереди,
ручные подтверждения и Telegram через HTTP-моки. Тестовый режим не выполняет
реальные публикации, лайки или доставку сообщений.

Реальный TikTok может изменить разметку или потребовать ручной вход. Работа
автозаполнения на настоящем аккаунте и запуск сборки на Windows требуют отдельной
ручной проверки. Итог текущего прогона — в [validation.md](validation.md).
