# RubUP Automation 3.0

**Пакетная подготовка заданий TikTok для двух аккаунтов на Windows 10/11.**
Вставьте до 100 ссылок, подготовьте по одному разному комментарию для каждого
аккаунта и продолжайте ручную публикацию из сохранённой очереди.

Основной сценарий: **50 ссылок → «НАЧАТЬ ПОДГОТОВКУ» → до 100 разных комментариев
→ ручная публикация и лайки для обоих аккаунтов → прямые ссылки в Telegram**.
Подготовленный текст не считается опубликованным, а одна подтверждённая публикация
не завершает задачу второго аккаунта.

Версия 2.0 сохранена в ветке [`backup-v2`](https://github.com/deakatsuxq/RubUP-TikTok-Automation/tree/backup-v2).
Разработка 3.0 идёт отдельно в [`rubup-v3`](https://github.com/deakatsuxq/RubUP-TikTok-Automation/tree/rubup-v3).
Ветка `main` не заменяется обновлением 3.0. Рабочая история, ключи и настройки сохраняются;
перед добавлением новых таблиц создаётся резервная копия SQLite.

## Установка и запуск без команд

1. Установите **Python 3.12, 64-bit** с [python.org](https://www.python.org/downloads/windows/).
   В установщике оставьте Python Launcher и отметьте **Add python.exe to PATH**.
2. Полностью распакуйте ZIP, например в `C:\Мои программы\RubUP`.
   Папка должна быть доступна для записи. Не запускайте файлы прямо из ZIP
   и не помещайте приложение в `Program Files`.
3. **Один раз откройте `install.bat` двойным нажатием.** Он создаст локальное
   окружение и установит зависимости. Дождитесь сообщения о завершении.
4. **Откройте `start.bat` двойным нажатием.** В дальнейшем используйте только его.
5. Мастер первого запуска поможет подключить OpenAI, Telegram и картинки.
   Любой необязательный шаг можно пропустить и нажать **«Попробовать бесплатно»**.

`start.bat` запускает графическое приложение без постоянного окна консоли. Во время
первой установки окно с ходом загрузки зависимостей остаётся открытым.
Пути с пробелами и русскими буквами передаются в сценариях в кавычках.
Запуск на настоящей Windows и сборка EXE в этой Linux-среде не проверялись.

Если Python не установлен или установка не завершилась, сценарий покажет понятное
сообщение и не удалит настройки. Для обновления зависимостей можно повторить `install.bat`.

## Пять разделов

- **Главная** — многострочное поле ссылок, импорт TXT, кнопка **«НАЧАТЬ ПОДГОТОВКУ»**,
  предварительная стоимость и прогресс видео, комментариев, публикаций и Telegram.
- **Очередь** — одна карточка на видео и два независимых блока аккаунтов: текст,
  ручная публикация, обязательный лайк, картинки и переход к следующему видео.
- **Аккаунты** — два username, браузерные профили и счётчики. Вход в TikTok всегда выполняете вы.
- **Настройки** — ключи, модель, лимит расходов, правила Telegram и четыре оригинальные картинки.
- **Помощь** — встроенный раздел **«Как пользоваться?»** с пошаговыми инструкциями.

Одиночные сервисы, прежние записи SQLite, CSV-экспорт и дополнительные проверки
предыдущей версии сохранены. Итоговые результаты тестов — [docs/validation.md](docs/validation.md),
подробности обновления — [docs/v3.md](docs/v3.md). Исторические снимки 2.0 остаются
в `docs/v2-*.png`; они не выдаются за интерфейс 3.0.

## Два аккаунта TikTok

Откройте **«Аккаунты»** и укажите username каждого. Слот №1 сохраняет прежний
локальный ID аккаунта; второй получает собственный постоянный ID. Переименование
не должно использоваться для обхода ограничения «один аккаунт — одно видео».
Пароли TikTok не нужны: программа не перехватывает cookies, токены или авторизацию.
Статус входа отображается как **неподтверждённый**, если программа не может его проверить.

Кнопка открытия использует официальный TikTok. Для отдельных существующих профилей
Chrome/Edge можно указать браузер и имя профиля, например `Profile 1`. Приложение
передаёт URL и `--profile-directory` обычному процессу браузера, без скрытой автоматизации.
Войдите самостоятельно и перед публикацией убедитесь, что выбран нужный аккаунт.
Если отдельный профиль не настроен, используется обычный браузер; он может быть открыт
под любым вашим аккаунтом. Наличие username не доказывает авторизацию.

## Подключение OpenAI

1. Откройте **Настройки → Искусственный интеллект**.
2. Нажмите **«Где взять API-ключ?»** или откройте
   [кабинет OpenAI](https://platform.openai.com/api-keys).
3. Создайте ключ и вставьте его в закрытое поле приложения. Кнопка рядом показывает
   или скрывает значение по вашему действию.
4. Нажмите **«Проверить и получить модели»**. Список заполняется ответом вашего API,
   а не вымышленными вариантами. Текущая модель до проверки не считается доступной.
5. Выберите модель и нажмите **«Сохранить настройки»**. Для обычной смены ключа/модели
   перезапуск не требуется. **«Экономичный вариант»** выбирает подходящий mini/nano
   из полученного списка, но не обещает самый низкий тариф.

Подписка ChatGPT не оплачивает API. Доступность модели, баланс и лимит расходов
проверяются в кабинете OpenAI. Реальная генерация может стоить денег. Перед
**«Сгенерировать другой»** приложение предупреждает о новом запросе. Уже сохранённый
черновик не генерируется и не оплачивается заново без причины.

Стоимость считается по фактическим токенам `usage` и вручную заданным тарифам модели.
Если тарифы неизвестны, цена показывается как неизвестная, а не нулевая.
Прогноз на 10 000 запросов не выполняет эти запросы. Формула стоимости USD:
`(входные токены × тариф входа + выходные токены × тариф выхода) / 1 000 000`.
Повторы вариантов, внешние источники, налоги, конвертация валют и кэш-скидки могут
изменять счёт; локальный прогноз не заменяет счёт провайдера.

## Подключение Telegram

1. В Telegram найдите **@BotFather** и отправьте `/newbot`.
2. Создайте своего бота, скопируйте токен и нажмите **Start** в диалоге с ним.
3. В **Настройки → Telegram** вставьте токен и Chat ID.
4. **«Проверить бота»** вызывает `getMe` и ничего не отправляет.
5. **«Отправить тестовую ссылку»** выполняется только после явного нажатия.
   Укажите настоящий, уже проверенный URL задачи из своей истории.
   В чат уйдёт только одна прямая ссылка, без пояснений и комментария.

Подробный способ получения Chat ID есть во встроенной помощи. Если вы уже знаете
идентификатор своего чата, достаточно вставить его. Для группы добавьте бота и
предоставьте право отправки сообщений. Проверка токена не доказывает право писать
в конкретный чат — это проверяет отдельная тестовая отправка.

При необходимости Chat ID можно получить локально через `getUpdates`, после
сообщения вашему боту. Не передавайте токен посторонним сервисам:

```powershell
$botToken = Read-Host "Введите токен бота локально"
$updates = Invoke-RestMethod -Uri ("https://api.telegram.org/bot{0}/getUpdates" -f $botToken)
$updates.result.message.chat | Select-Object id, title, username
Remove-Variable botToken, updates
```

При активном webhook `getUpdates` может быть недоступен. Не удаляйте чужой webhook;
при необходимости создайте отдельного бота. Ключи никогда не отправляйте в чат поддержки.

В пакетном режиме действует отдельная сохранённая очередь доставки. По умолчанию
URL отправляется автоматически только после выполнения требований **обоими** аккаунтами:
публикации, нужной картинки и обязательного лайка. Одна публикация не завершает вторую.
Можно выбрать другой этап отправки либо выключить её в настройках пакетного режима.
Старый режим одиночной отправки остаётся совместимым.

Telegram получает только прямой URL, по одной ссылке в сообщении. При неизвестном
результате сообщение могло дойти: автоматический повтор блокируется. Подтверждённые
URL повторно не отправляются, в том числе после перезапуска. Ошибка доставки не стирает
прогресс публикаций. Не удаляйте базу ради повторной отправки.

## Как подготовить и опубликовать партию

1. Скопируйте ссылки TikTok, вставьте **по одной в строке** на Главной либо импортируйте TXT.
   За один импорт принимается 1–100 ссылок. Поддерживаются `vt.tiktok.com`, `vm.tiktok.com`
   и прямые адреса видео. Ошибочные адреса отмечаются, дубликаты исключаются из очереди,
   а история остаётся на месте.
2. Нажмите **«НАЧАТЬ ПОДГОТОВКУ»**. Проверьте количество новых запросов, тариф и оценку
   стоимости, затем подтвердите запуск. Для 50 ещё не обработанных подходящих видео
   возможны до 100 комментариев — по одному на аккаунт.
3. Дождитесь результата либо используйте **Пауза**, **Продолжить**, **Остановить**.
   Текущий сетевой запрос завершается по тайм-ауту; прогресс сохраняется между операциями.
   После перезапуска повторно вставлять список не нужно.
4. В **Очереди** откройте видео. Если дата или тематика неизвестны, проверьте оригинал
   и заполните только недостающие сведения. Предварительный черновик не считается
   окончательно подходящим оплачиваемым заданием. По умолчанию дата — от `2026-05-01`,
   нужен включённый хештег или ключевое слово.
5. Для аккаунта №1 проверьте комментарий, нажмите **«Скопировать комментарий»**
   и **«Открыть TikTok»**. Убедитесь, что открыт правильный аккаунт. Опубликуйте текст
   и нужную картинку самостоятельно.
6. Нажмите **«Я опубликовал»** и подтвердите только фактические действия. Если требуется
   лайк, поставьте его в TikTok и отдельно нажмите **«Я поставил лайк»**. Непоставленный
   обязательный лайк оставляет аккаунт незавершённым.
7. Повторите действия для аккаунта №2. Комментарии должны различаться формулировкой;
   одинаковые и чрезмерно похожие варианты отклоняются относительно сохранённой истории.
   RubUP/@RubUP/форма «рубап» и нужная рекламная маркировка обязательны. Не подтверждайте
   вымышленные подарки, выигрыши и личный опыт.
8. По умолчанию после выполнения требований обоими аккаунтами URL попадает в очередь
   Telegram. **«Следующее видео»** открывает следующую незавершённую карточку.
   Горячие клавиши: **Ctrl+1**, **Ctrl+2** — копирование для аккаунтов; **Ctrl+→** — следующее видео.

Готовые и опубликованные пары аккаунт/видео не генерируются заново без необходимости.
При ошибке повторяйте только неуспешную задачу. Новый вариант текста — новый возможный
платный запрос; программа предупреждает перед его запуском.

Для коротких ссылок каждый переход проверяется до сетевого обращения, число переходов
и время ограничены. Не разрешены посторонние сайты и локальные IP. Если TikTok не раскрывает
ссылку, откройте её в браузере и скопируйте полный адрес. CAPTCHA и защиту приложение не обходит.
Глобального поиска по всему TikTok нет: обрабатываются ваши ссылки. Прежние форматы импорта
описаны в [docs/import_format.md](docs/import_format.md).

## Лимит расходов перед большой партией

Настройте `batch_budget_usd` — максимальную сумму USD для партии; пустое значение
означает, что локальный лимит не установлен. Цены входных и выходных токенов вводятся
по действующему тарифу выбранной модели. Если лимит задан, но цены неизвестны,
платные запросы блокируются, а не считаются бесплатными.

Перед каждым запросом резервируется консервативная оценка: верхняя граница входа
по UTF-8-байтам инструкций и контекста плюс запас, затем максимум выходных токенов.
Это техническая оценка, не точный подсчёт токенов. После ответа резерв сверяется
с фактическим `usage`. Повторные варианты тоже учитываются. Потерянный ответ может
означать неизвестную оплату: дальнейшая платная обработка приостанавливается,
а неопределённая сумма не обнуляется при перезапуске.

Предварительный расчёт перед запуском основан на явно показанных предположениях.
Он не заменяет счёт OpenAI. Налоги, конвертация и сторонние расходы учитываются отдельно.

## Картинки и история

В **Настройках → Картинки** добавьте свои четыре JPG/JPEG/PNG. Исходные байты и размер
сохраняются, оригиналы проверяются декодированием и SHA-256. В поставке картинок нет.
Поддерживаются режимы: без картинок, чередование четырёх, конкретная и по требованиям
задания. Картинка используется только для задания, которому она нужна.

Порядок и история выбора сохраняются. Если слот заменён после подготовки, старая
задача не получит новую картинку незаметно; прежняя копия остаётся в `images/archive`.
Восстановите исходный оригинал либо явно измените требования и повторно проверьте
черновик. Открытие нужного изображения перед ручной публикацией доступно из результата.

**Очередь** и прежние сервисы сохраняют историю. Статусы показаны обычными русскими словами.
Внутренние состояния SQLite не удаляются и не объединяются. Пара аккаунт/видео защищена
от повторного оплачиваемого комментария, нормализованный текст — от дубликатов.
Подтверждения публикации, подачи/принятия отчёта и вознаграждения остаются отдельными.
CSV-экспорт сохранён. Стабильный ID аккаунта задаётся в дополнительных настройках;
смена идентификатора не предназначена для обхода лимитов.

## Бесплатная демонстрация

**«Попробовать бесплатно»** показывает 50 явно тестовых видео и 100 разных черновиков
для двух аккаунтов в отдельной базе. Платные API не вызываются. Тестовые URL не являются
утверждением о существовании реальных видео. В демо нельзя подтвердить реальные публикации,
лайки или вознаграждения, отправить Telegram-сообщения или изменить рабочую историю.
Оригиналы и порядок чередования пользовательских картинок не меняются.

Сверху отображается **«Демонстрационный режим — реальные действия не выполняются»**.
Мастер настройки можно открыть повторно; пропущенное подключение не считается успешным.

## Ключи, обновление и резервные копии

На Windows ключи из приложения защищаются **DPAPI текущего пользователя Windows**
в `data/credentials.dpapi`. Файл не предназначен для переноса между пользователями
или компьютерами. На Linux используется локальный `.env` с ограничением прав.
Существующие `.env` и переменные окружения по-прежнему поддерживаются.
Ключи не попадают в `config.yaml`, логи, Git или ZIP; поля скрыты по умолчанию.
Не включайте сторонние HTTP-debug логи: Telegram содержит токен в адресе API-запроса.

Перед обновлением закройте приложение и сделайте резервную копию `data`, `images`,
`config.yaml` и отдельно `.env` в защищённое место. Активную SQLite-базу не копируйте
одним файлом во время записи. Новая версия сохраняет прежние данные и настройки;
не заменяйте ваш `config.yaml` шаблоном из ZIP. Копируйте обновлённые исходники и GUI,
оставляя пользовательские файлы на месте, затем выполните `install.bat`.
Старые таблицы и строки SQLite сохраняются. Перед первым добавлением таблиц 3.0
программа создаёт согласованную SQLite-копию в `backups` рядом с базой. Если резервное
копирование не удалось, обновление схемы не продолжается. Новые профили, партии,
очередь Telegram и бюджет хранятся отдельно от прежних записей. Первый профиль
сохраняет старый ID аккаунта; ни один старый комментарий не переназначается.

Версия 2.0 доступна в `backup-v2`, а `main` остаётся на ней. Для безопасного отката
используйте копию прежней базы и настроек в отдельной папке; не удаляйте новые данные
и не подменяйте рабочую базу во время запуска. Локальная резервная копия перед разработкой
создана вне репозитория, поэтому её ключи и данные не попадают в GitHub или ZIP.

Смена пути базы, локального аккаунта или изолированного режима может потребовать
перезапуска; приложение сообщает об этом. Обычные настройки модели, ключей,
Telegram и изображений применяются без перезапуска.

## Если что-то не получилось

- **Неверный ключ или модель:** проверьте ключ и заново получите доступные модели.
- **Недостаточно средств:** проверьте баланс и лимит API OpenAI. Подписка ChatGPT отдельно.
- **Бот не отвечает:** нажмите Start, проверьте токен, Chat ID и права бота в чате.
- **Ссылка не открывается:** откройте её в браузере и скопируйте прямой адрес ролика.
- **Нет сведений о видео:** заполните только отмеченные отсутствующие данные вручную.
- **Комментарий не появился:** прочитайте сообщение, проверьте сеть/ключ и попробуйте
  после устранения причины. Не запускайте новые платные запросы при неизвестном результате прежнего.
- **Видео уже обработано:** откройте сохранённую карточку в Очереди вместо новой генерации.
- **Нет Интернета:** история и демо доступны; для реальных API дождитесь подключения.
- **Не удалось установить:** убедитесь, что установлен Python 3.12 с Python Launcher.
  Не отключайте TLS, проверку сертификатов или системную защиту ради установки.

Подробные решения доступны в разделе **Помощь**. Технические сведения остаются в
`logs/rubup.log`. Нужные сетевые узлы: `api.openai.com`, `api.telegram.org`,
`www.tiktok.com`, `tiktok.com`, `vt.tiktok.com`, `vm.tiktok.com`.
Текущая документация TikTok ранее блокировалась прокси среды разработки (403),
доступный публичный механизм автопубликации не подтверждён. Подробнее:
[docs/tiktok_api.md](docs/tiktok_api.md).

## Для разработчиков: команды и проверка

Команды необязательны для повседневного запуска:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe main.py --batch-demo
.\.venv\Scripts\python.exe main.py --dry-run
.\.venv\Scripts\python.exe main.py --import-file .\videos.csv
.\.venv\Scripts\python.exe main.py --status
.\.venv\Scripts\python.exe main.py --prepare
.\.venv\Scripts\python.exe main.py --export .\history.csv
.\.venv\Scripts\python.exe -m pytest -q
```

Пакетная демонстрация использует `data/batch_demo.sqlite3`; прежний CLI dry-run —
`data/dry_run.sqlite3`; рабочая база по умолчанию —
`data/history.sqlite3`. Тесты работают с временными базами и HTTP-моками, без реальных
публикаций, сообщений и платных запросов. Для Linux без дисплея установите
`QT_QPA_PLATFORM=offscreen`. Результаты текущего прогона: [docs/validation.md](docs/validation.md).
Обзор 3.0: [docs/v3.md](docs/v3.md). История 2.0: [docs/v2.md](docs/v2.md).

## Сборка Windows EXE и ZIP

Если нужен запуск без установленного Python, соберите EXE **на Windows** после
установки зависимостей:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_windows.ps1
```

Результат: новая папка `dist\RubUP-Automation-3.0-<дата-время>\RubUP-Automation`
с `RubUP-Automation.exe`, без отдельной консоли. Сценарий не пересобирает поверх
папки, где могли появиться ваши настройки и база. Для передачи копируйте **всю**
полученную папку приложения, не один EXE.
Ключи, базы и оригиналы картинок не копируются сборщиком. Настройте их в мастере
при первом запуске. Сборка не подписана. Windows-сборка и её запуск здесь **не проверены**;
Linux не используется для заявления о готовом проверенном Windows EXE.

ZIP исходников собирается без окружения, ключей и пользовательских данных:

```powershell
.\.venv\Scripts\python.exe tools\package_project.py
```

По умолчанию создаётся `RubUP-Automation-3.0-Windows.zip` рядом с папкой проекта.
Это архив исходников и сценариев для Windows, а не заявление о проверенном Windows EXE.
Старый архив версии 2.0 автоматически не удаляется.

Архив содержит исходники, тесты, установочные сценарии, документацию, доступные
скриншоты и `SHA256SUMS.txt`. Существующий архив заменяется только после успешной
проверки нового. `.env`, DPAPI-хранилище, базы, логи, пользовательские изображения
и вложенный ZIP из репозитория в него не включаются.
