# RubUP TikTok Automation

Локальная программа на Python 3.12 и PySide6 для подготовки заданий TikTok:
импорт ссылок, тематическая проверка, комментарии через OpenAI, четыре оригинальные
картинки, ручная публикация, отправка прямых ссылок в Telegram и история SQLite.
Интерфейс на русском языке, в тёмной теме. VPS и сервер не нужны.

**Реализован режим подготовки с ручной публикацией. Глобальный поиск TikTok и
автоматическая публикация комментариев не реализованы.** Неизвестные метаданные
не заменяются выдуманными. Проверка текущей документации TikTok из среды разработки
блокировалась прокси 403; подробности и официальные ссылки — [docs/tiktok_api.md](docs/tiktok_api.md).

| Функция | Реализована | Требует API | Требует ручного действия |
|---|---|---|---|
| Поиск видео | Фильтрация импортированных ссылок по хештегам/словам и дате; глобального поиска нет | Нет | Импортировать ссылки |
| Метаданные | CSV/JSON, редактор; дополнительный oEmbed для известной ссылки | Только oEmbed; живой доступ не проверен | Проверить дату, отсутствующие сведения |
| Генерация комментария | OpenAI Responses API, до двух исправлений, RubUP, уникальность, маркировка | Ключ OpenAI | Проверить достоверность черновика |
| Публикация комментария | Копирование, открытие видео, чек-лист подтверждения | Автопубликации нет | Опубликовать в TikTok |
| Использование картинки | Четыре оригинала, SHA-256, чередование, выбор по заданию, история | Нет | Добавить оригиналы и прикрепить в TikTok |
| Telegram | Одна прямая ссылка в одном сообщении, защита от повторов | Telegram Bot API | Настроить бота и явно запустить отправку |

Внешние API покрыты тестовыми HTTP-клиентами. Реальная генерация и отправка без
ваших ключей не проверены. Linux-проверка GUI не заменяет приёмку на Windows.

## Установка Windows 10/11

1. Скачайте Python 3.12 для Windows с [python.org](https://www.python.org/downloads/windows/).
   При установке отметьте **Add python.exe to PATH**. Используйте 64-битную версию.
2. Распакуйте ZIP в доступную для записи папку, например `C:\RubUP`.
   Не запускайте из архива и не устанавливайте в `Program Files`.
3. Откройте папку в Проводнике. В адресной строке введите `powershell` и нажмите Enter.
4. Выполните команды по очереди:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

Если `.env` уже существует, не копируйте шаблон поверх него. Активация виртуального
окружения не обязательна: команды используют его Python напрямую.

Для проверки без ключей:

```powershell
.\.venv\Scripts\python.exe main.py --dry-run
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe main.py
```

После установки запускайте `start.bat` двойным нажатием. Нужны Интернет для API и
браузер либо приложение TikTok для ручных действий. Локальная база работает без сети.

## OpenAI и Telegram

В [кабинете OpenAI](https://platform.openai.com/api-keys) создайте API-ключ,
проверьте доступность выбранной модели и лимит расходов. Доступ к ChatGPT сам по себе
не заменяет оплату API. Модель по умолчанию — `gpt-4.1-mini`, её можно изменить.

В Telegram найдите **@BotFather**, отправьте `/newbot`, задайте имя и username бота.
Сохраните полученный токен в `.env`, затем откройте своего бота и нажмите **Start**.
Для группы добавьте бота в нужный чат и предоставьте право отправки сообщений.

Чтобы получить Chat ID без отправки секретного токена сторонним ботам, после сообщения
вашему боту выполните в PowerShell:

```powershell
$botToken = Read-Host "Введите токен бота локально"
$updates = Invoke-RestMethod -Uri ("https://api.telegram.org/bot{0}/getUpdates" -f $botToken)
$updates.result.message.chat | Select-Object id, title, username
Remove-Variable botToken, updates
```

Команда читает сообщения, не отправляет их. При пустом результате напишите боту ещё раз.
При активном webhook `getUpdates` может быть недоступен: используйте конфигурацию
существующего бота или создайте отдельного для программы. Не удаляйте чужой webhook.
Токен вводится локально; не отправляйте его в чат поддержки и не прикладывайте `.env`.

Содержимое `.env` (значения ниже — пустой шаблон):

```dotenv
OPENAI_API_KEY=
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

Вставьте свои значения после `=` и перезапустите программу. Секреты читаются только
из окружения/`.env`; интерфейс не показывает и не сохраняет их в YAML. Файлы `.env`,
локальные данные, картинки и логи исключены из Git и итогового ZIP.

На вкладке подключений нажмите проверку OpenAI и Telegram. OpenAI читает список
моделей, Telegram вызывает `getMe` **без отправки сообщения**. Проверка Telegram не
доказывает право писать в конкретный чат. Для проверки доставки импортируйте реальную
ссылку, заполните дату и описание, выберите в настройках нужный режим Telegram,
перезапустите приложение и явно нажмите отправку ссылок. Убедитесь, что в чате пришёл
только URL. Не используйте вымышленные тестовые ссылки dry-run для реального отчёта.

## Первый рабочий цикл

1. В настройках задайте стабильный ID своего TikTok-аккаунта. Это локальный ключ
   учёта; авторизация TikTok не выполняется. Смена идентификатора не является способом
   обходить лимит одного оплачиваемого комментария на ролик.
2. Добавьте прямую ссылку кнопкой **Добавить URL** или импортируйте TXT/CSV/JSON.
   Поддерживается вид `https://www.tiktok.com/@username/video/123456789`.
   Короткие ссылки `vm.tiktok.com` сначала откройте в браузере и скопируйте прямую.
3. Укажите дату публикации и описание с хештегами после проверки оригинального видео.
   Дополнительная кнопка oEmbed получает только сведения, действительно возвращённые
   TikTok. Даты она не добавляет. Формат импорта: [docs/import_format.md](docs/import_format.md).
4. Поиск проверит локальные записи: дата от `2026-05-01`, включённый хештег **или**
   ключевое слово. Неизвестная/некорректная/будущая дата требует ручной проверки.
5. При необходимости задайте требования картинки и лайка для выбранной задачи.
   Нажмите обработку либо генерацию выбранного ролика. Реальная генерация платная.
6. Проверьте текст, при необходимости отредактируйте, нажмите **Проверить и сохранить**.
   Каждый комментарий должен содержать RubUP/@RubUP/допустимую форму «рубап».
   Реклама по умолчанию требует слова «реклама». Неподтверждённые выигрыши,
   подарки и личный опыт запрещены инструкцией генератора; человеческая проверка обязательна.
7. Скопируйте текст, откройте видео и нужный оригинал картинки. Опубликуйте вручную.
   Отметьте фактически выполненные пункты и подтвердите публикацию.
8. Запустите отправку ссылок в Telegram. Режим задаёт допустимый этап: проверено,
   черновик подготовлен либо публикация подтверждена. Отправка не подтверждает публикацию.
9. Если отчёт действительно подан/принят, отметьте это отдельными кнопками.
   Вознаграждение подтверждается отдельно, с фактически начисленной суммой.

Остановка прекращает цикл между операциями. Текущий запрос завершается по тайм-ауту;
не закрывайте процесс принудительно. Пауза и продолжение не удаляют очередь. При
следующем запуске незавершённые задачи берутся из SQLite. Ошибочную задачу можно
повторно подготовить выбором ролика; валидный сохранённый текст автоматически заново
не оплачивается. **Сгенерировать заново** означает новый платный запрос.

Периодический поиск повторяет проверку локального импорта, не ищет новые ролики
во всём TikTok. Таблица поддерживает сортировку, текстовый фильтр и фильтр статусов.
История показывает события и позволяет экспортировать CSV для Excel.

## Четыре изображения

На вкладке изображений добавьте **свои четыре** JPG/JPEG/PNG. В поставке оригиналов
нет — они не были приложены к заданию. Программа не заменяет их сгенерированными.
Копируются исходные байты, размеры не изменяются. Проверяются декодирование и SHA-256;
изменённый/повреждённый файл не допускается к подтверждению.

В настройках: без картинки, чередование всех четырёх, конкретный номер либо номер
из требований задачи. Картинка выбирается только когда задание её требует.
Для чередования должны быть добавлены все четыре целых оригинала. Порядок сохраняется
между запусками. История хранит выбор для подготовки, **не доказательство публикации**.
Если слот заменён после подготовки, старая задача не получит новую картинку незаметно:
восстановите прежний оригинал либо явно измените требования и повторно проверьте черновик.

## Настройки и расходы

Всё, кроме секретов, хранится в `config.yaml`. Настройки интерфейса сохраняют этот
файл; для применения перезапустите приложение. Список хештегов отдельный от кода,
исходные 27 тегов уже заполнены. Теги можно добавлять, удалять и отключать.

- `max_videos` ограничивает задачи за цикл, `search_interval` — интервал секунд.
- `target_per_minute` ограничивает темп подготовки, не обещает скорость публикаций.
- `max_context_chars` ограничивает длину JSON-контекста в символах; это **не** число токенов.
- `max_output_tokens` — ограничение ответа OpenAI; `max_comment_length` — символы комментария.
- `retries`, `timeout` ограничивают повторы и длительность HTTP-запросов.
- `input_price_per_million`, `output_price_per_million` — ручные тарифы USD за миллион
  токенов. Пустые значения означают **неизвестную стоимость**, а не бесплатную генерацию.
- `third_party_cost` — отдельная фиксированная оценка затрат на источник данных, USD.
- `reward_default`, `reward_by_image` — ожидаемая сумма за задачу в вашей валюте
  вознаграждений; эти числа не смешиваются с подтверждённой оплатой и расходами USD.

Смотрите прогноз на 10 000 запросов на вкладке истории. Он не запускает генерацию.
Формула: `(входные токены × тариф входа + выходные токены × тариф выхода) / 1 000 000`.
Прогноз использует 250 входных и 40 выходных токенов на запрос; реальные данные могут
существенно отличаться. Для своей оценки используйте `CostTracker.estimate(...)`.
До двух повторных вариантов также могут оплачиваться. Учёт основан на реальном
`usage` API; отклонённые ответы учитываются. При потерянном ответе возможная стоимость
помечается неизвестной, автоматический повтор платного запроса не делается.
Скидки за кэширование, пакетные тарифы, налоги и конвертация валют отдельно не моделируются;
локальная оценка не заменяет счёт провайдера.

## Dry-run, CLI и тесты

```powershell
.\.venv\Scripts\python.exe main.py --dry-run
.\.venv\Scripts\python.exe main.py --import-file .\videos.csv
.\.venv\Scripts\python.exe main.py --status
.\.venv\Scripts\python.exe main.py --prepare
.\.venv\Scripts\python.exe main.py --export .\history.csv
.\.venv\Scripts\python.exe -m pytest -q
```

Dry-run сохраняет явно помеченные синтетические задачи в `data/dry_run.sqlite3`,
использует тестовый генератор и отдельный каталог изображений. Он не доказывает
существование тестовых URL, не вызывает OpenAI/TikTok/Telegram, не подтверждает
публикации, отчёты или оплату и не меняет рабочую историю. Повторный запуск использует
сохранённые тестовые черновики. Для чистого dry-run закройте программу и удалите только
`data/dry_run.sqlite3` с её `-wal`/`-shm`, оставив рабочую базу нетронутой.

Тесты используют временные базы и HTTP-моки; не публикуют комментарии и не отправляют
сообщения. Для Linux без дисплея GUI проверяется с `QT_QPA_PLATFORM=offscreen`.

## Сохранность и устранение ошибок

- База по умолчанию: `data/history.sqlite3`. Уникальное ограничение защищает пару
  аккаунт/видео; нормализованный текст также не допускает повторов.
- Не удаляйте рабочую базу ради исправления ошибки. Для резервного копирования
  завершите приложение и скопируйте `data`, `images`, `config.yaml` и отдельно `.env`
  в защищённое место. Активную SQLite-базу не копируйте одним файлом во время записи.
- Если дата неизвестна, заполните её вручную; галочка не заменяет дату и тематику.
- HTTP 401/403: проверьте ключ, права, оплату/доступность модели и сетевую политику.
- Telegram 400/403: откройте диалог с ботом, проверьте Chat ID и права в группе.
- Telegram `UNKNOWN` или зависшая `RESERVED`: сообщение могло дойти; автоматическая
  повторная отправка блокируется. Проверьте чат вручную. Программа предпочитает
  возможную недоставку повторной ссылке; автоматического снятия этой защиты нет.
- 429: ограничение частоты. Не обходите его; дождитесь разрешённого времени и повторите.
- Если Python не найден, переустановите Python 3.12 с PATH и откройте новое окно PowerShell.
- Если `No module named ...`, используйте именно `.venv\Scripts\python.exe` и повторите
  установку requirements. Не отключайте TLS и проверку подписей для обхода ошибок установки.
- Нет подключения: для нужных функций разрешите `api.openai.com`, `api.telegram.org`,
  `www.tiktok.com`; для документации — `developers.tiktok.com`, `platform.openai.com`,
  `core.telegram.org`. Локальные проверки и dry-run не требуют этих узлов.
- Техническая информация остаётся в `logs/rubup.log` и истории; токены редактируются,
  тела ответов API не выводятся. Не включайте HTTP-debug логи сторонними настройками.

## Сборка EXE и ZIP

Для Windows предусмотрен сценарий PyInstaller:

```powershell
powershell -ExecutionPolicy Bypass -File .\build_windows.ps1
```

Это локальная сборка в папку `dist\RubUP`; ключи и оригиналы картинок туда не
копируются. Рядом с EXE нужны `config.yaml`, ваш `.env` и доступная для записи папка.
Сборка EXE на Windows в этой Linux-среде **не выполнялась и не проверена**.
Полученный EXE не подписан. Если Windows блокирует запуск, проверяйте источник
и подпись самостоятельно; не отключайте системную защиту.

Архив исходников создаётся без окружения, ключей и пользовательских данных:

```powershell
.\.venv\Scripts\python.exe tools\package_project.py
```

Файлы проекта: `application.py` объединяет сервисы; `scheduler.py` — кооперативную
очередь; `database.py` — транзакции/состояния; `gui/` — интерфейс; остальные модули
отвечают за поиск, анализ, комментарии, изображения, Telegram, отчёты и расходы.
