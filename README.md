# RubUP Automation 2.0

**Помощник для заданий TikTok на Windows 10/11.** Вставьте ссылку, получите короткий
комментарий, проверьте его и опубликуйте вручную. Приложение сохраняет задания,
картинки и историю, помогает отправлять в Telegram только прямые ссылки.

Основной сценарий: **открыл → вставил ссылку → начал обработку → проверил комментарий
→ опубликовал → отправил ссылку**. Настройки ключей и встроенная помощь находятся
в приложении; редактировать `.env` или YAML для обычной работы не нужно.

## Установка и запуск без команд

1. Установите **Python 3.12, 64-bit** с [python.org](https://www.python.org/downloads/windows/).
   В установщике оставьте Python Launcher и отметьте **Add python.exe to PATH**.
2. Полностью распакуйте ZIP, например в `C:\Мои программы\RubUP`.
   Папка должна быть доступна для записи. Не запускайте файлы прямо из ZIP
   и не помещайте приложение в `Program Files`.
3. **Один раз откройте `install.bat` двойным нажатием.** Он создаст локальное
   окружение и установит зависимости. Дождитесь сообщения о завершении.
4. **Откройте `start.bat` двойным нажатием.** В дальнейшем используйте только его.
5. Мастер первого запуска поможет подключить OpenAI, Telegram и картинки.
   Любой необязательный шаг можно пропустить и нажать **«Попробовать бесплатно»**.

`start.bat` запускает графическое приложение без постоянного окна консоли. Во время
первой установки окно с ходом загрузки зависимостей остаётся открытым.
Пути с пробелами и русскими буквами передаются в сценариях в кавычках.
Запуск на настоящей Windows и сборка EXE в этой Linux-среде не проверялись.

Если Python не установлен или установка не завершилась, сценарий покажет понятное
сообщение и не удалит настройки. Для обновления зависимостей можно повторить `install.bat`.

## Пять разделов

- **Главная** — поле ссылки, кнопка **«НАЧАТЬ ОБРАБОТКУ»**, три показателя и последний результат.
- **Мои задания** — карточки истории, фильтры, открытие и продолжение. Импорт и экспорт,
  подробные сведения, требования и отчёты сохранены в дополнительных действиях.
- **Картинки** — четыре оригинала, превью, добавление/замена и режим выбора.
- **Настройки** — ключи, доступная модель, Telegram и дополнительные параметры.
- **Помощь** — встроенные инструкции: первый запуск, видео, картинки, частые ошибки
  и объяснение ручных действий. Для обычной работы не нужно возвращаться к README.

Снимки интерфейса: [главная](docs/v2-home.png), [демонстрация](docs/v2-demo.png),
[мастер первого запуска](docs/v2-wizard.png). Проверка обновления: **299 тестов прошли**,
включая все прежние 176. Подробности — [результаты проверки](docs/validation.md).

## Подключение OpenAI

1. Откройте **Настройки → Искусственный интеллект**.
2. Нажмите **«Где взять API-ключ?»** или откройте
   [кабинет OpenAI](https://platform.openai.com/api-keys).
3. Создайте ключ и вставьте его в закрытое поле приложения. Кнопка рядом показывает
   или скрывает значение по вашему действию.
4. Нажмите **«Проверить и получить модели»**. Список заполняется ответом вашего API,
   а не вымышленными вариантами. Текущая модель до проверки не считается доступной.
5. Выберите модель и нажмите **«Сохранить настройки»**. Для обычной смены ключа/модели
   перезапуск не требуется. **«Экономичный вариант»** выбирает подходящий mini/nano
   из полученного списка, но не обещает самый низкий тариф.

Подписка ChatGPT не оплачивает API. Доступность модели, баланс и лимит расходов
проверяются в кабинете OpenAI. Реальная генерация может стоить денег. Перед
**«Сгенерировать другой»** приложение предупреждает о новом запросе. Уже сохранённый
черновик не генерируется и не оплачивается заново без причины.

Стоимость считается по фактическим токенам `usage` и вручную заданным тарифам модели.
Если тарифы неизвестны, цена показывается как неизвестная, а не нулевая.
Прогноз на 10 000 запросов не выполняет эти запросы. Формула стоимости USD:
`(входные токены × тариф входа + выходные токены × тариф выхода) / 1 000 000`.
Повторы вариантов, внешние источники, налоги, конвертация валют и кэш-скидки могут
изменять счёт; локальный прогноз не заменяет счёт провайдера.

## Подключение Telegram

1. В Telegram найдите **@BotFather** и отправьте `/newbot`.
2. Создайте своего бота, скопируйте токен и нажмите **Start** в диалоге с ним.
3. В **Настройки → Telegram** вставьте токен и Chat ID.
4. **«Проверить бота»** вызывает `getMe` и ничего не отправляет.
5. **«Отправить тестовую ссылку»** выполняется только после явного нажатия.
   Укажите настоящий, уже проверенный URL задачи из своей истории.
   В чат уйдёт только одна прямая ссылка, без пояснений и комментария.

Подробный способ получения Chat ID есть во встроенной помощи. Если вы уже знаете
идентификатор своего чата, достаточно вставить его. Для группы добавьте бота и
предоставьте право отправки сообщений. Проверка токена не доказывает право писать
в конкретный чат — это проверяет отдельная тестовая отправка.

При необходимости Chat ID можно получить локально через `getUpdates`, после
сообщения вашему боту. Не передавайте токен посторонним сервисам:

```powershell
$botToken = Read-Host "Введите токен бота локально"
$updates = Invoke-RestMethod -Uri ("https://api.telegram.org/bot{0}/getUpdates" -f $botToken)
$updates.result.message.chat | Select-Object id, title, username
Remove-Variable botToken, updates
```

При активном webhook `getUpdates` может быть недоступен. Не удаляйте чужой webhook;
при необходимости создайте отдельного бота. Ключи никогда не отправляйте в чат поддержки.

Рабочая отправка также запускается явно и учитывает выбранный этап: видео проверено,
комментарий готов либо публикация подтверждена. Одна ссылка — одно сообщение.
Если сообщение могло дойти, но ответ потерян, повтор блокируется. Проверяйте чат
вручную; неизвестная доставка не считается ни подтверждённой отправкой, ни безопасным
основанием для повтора.

## Как обработать видео

1. Скопируйте ссылку в TikTok и вставьте на **Главной**.
   Поддерживаются прямые адреса и короткие `vt.tiktok.com` / `vm.tiktok.com`.
2. Нажмите **«НАЧАТЬ ОБРАБОТКУ»**. Программа проверит ссылку, дубликаты и доступные
   метаданные, затем подготовит комментарий через OpenAI.
3. Проверьте карточку результата. Неизвестные сведения явно отмечаются.
   Если дата или тематика отсутствуют, можно получить **предварительный черновик**;
   это ещё не подходящее оплачиваемое задание.
4. Нажмите проверку недостающих сведений, откройте реальный ролик и заполните только
   то, что не удалось получить. Дата по умолчанию должна быть не раньше `2026-05-01`.
   Требуются включённый хештег или ключевое слово и допустимая дата.
5. Проверьте комментарий. RubUP/@RubUP/допустимая форма «рубап» обязательны.
   Рекламная маркировка по умолчанию включена. Не подтверждайте вымышленные подарки,
   выигрыши или личный опыт: проверка текста человеком остаётся обязательной.
6. **Скопируйте комментарий**, **откройте TikTok** и прикрепите нужную картинку вручную,
   если задание её требует. Приложение не публикует комментарий само.
7. После реального действия нажмите **«Я опубликовал»** и отметьте фактически выполненные
   обязательные пункты. Если дата/тематика ещё не проверены, подтверждение не пройдёт.
8. После подтверждения можно отправить ссылку в Telegram. Отправка не подменяет
   подтверждение публикации, принятия отчёта или начисления денег.

Разрешены только HTTPS-адреса TikTok. Для коротких ссылок каждый переход проверяется,
число переходов и время ограничены. Если TikTok блокирует раскрытие, откройте ссылку
в браузере и скопируйте полный адрес. CAPTCHA и защиту приложение не обходит.
Глобального поиска по всем видео TikTok нет: сохранены локальные фильтры и импорт
списков. Форматы TXT/CSV/JSON описаны в [docs/import_format.md](docs/import_format.md).

## Картинки и история

В разделе **Картинки** добавьте свои четыре JPG/JPEG/PNG. Исходные байты и размер
сохраняются, оригиналы проверяются декодированием и SHA-256. В поставке картинок нет.
Поддерживаются режимы: без картинок, чередование четырёх, конкретная и по требованиям
задания. Картинка используется только для задания, которому она нужна.

Порядок и история выбора сохраняются. Если слот заменён после подготовки, старая
задача не получит новую картинку незаметно; прежняя копия остаётся в `images/archive`.
Восстановите исходный оригинал либо явно измените требования и повторно проверьте
черновик. Открытие нужного изображения перед ручной публикацией доступно из результата.

**Мои задания** сохраняют прежнюю историю. Статусы показаны обычными русскими словами.
Внутренние состояния SQLite не удаляются и не объединяются. Пара аккаунт/видео защищена
от повторного оплачиваемого комментария, нормализованный текст — от дубликатов.
Подтверждения публикации, подачи/принятия отчёта и вознаграждения остаются отдельными.
CSV-экспорт сохранён. Стабильный ID аккаунта задаётся в дополнительных настройках;
смена идентификатора не предназначена для обхода лимитов.

## Бесплатная демонстрация

**«Попробовать бесплатно»** работает без ключей и платных запросов. Вы увидите карточку
результата с явной надписью **«Демонстрационный режим — реальные действия не выполняются»**.
Используются синтетические данные и тестовый генератор. Демо не доказывает существование
тестовых URL, не публикует комментарии, не отправляет сообщения и не меняет рабочую историю,
картинки или чередование. Данные демо хранятся отдельно от рабочих.

Мастер первого запуска показывается до его завершения; открыть его повторно можно
через настройки. Пропуск подключения не означает успешное подключение.

## Ключи, обновление и резервные копии

На Windows ключи из приложения защищаются **DPAPI текущего пользователя Windows**
в `data/credentials.dpapi`. Файл не предназначен для переноса между пользователями
или компьютерами. На Linux используется локальный `.env` с ограничением прав.
Существующие `.env` и переменные окружения по-прежнему поддерживаются.
Ключи не попадают в `config.yaml`, логи, Git или ZIP; поля скрыты по умолчанию.
Не включайте сторонние HTTP-debug логи: Telegram содержит токен в адресе API-запроса.

Перед обновлением закройте приложение и сделайте резервную копию `data`, `images`,
`config.yaml` и отдельно `.env` в защищённое место. Активную SQLite-базу не копируйте
одним файлом во время записи. Новая версия сохраняет прежние данные и настройки;
не заменяйте ваш `config.yaml` шаблоном из ZIP. Копируйте обновлённые исходники и GUI,
оставляя пользовательские файлы на месте, затем выполните `install.bat`.
Структура SQLite сохраняется: новые сведения о проверке черновика находятся
в уже существующем JSON-чек-листе. Миграция с удалением старых таблиц не нужна.

Смена пути базы, локального аккаунта или изолированного режима может потребовать
перезапуска; приложение сообщает об этом. Обычные настройки модели, ключей,
Telegram и изображений применяются без перезапуска.

## Если что-то не получилось

- **Неверный ключ или модель:** проверьте ключ и заново получите доступные модели.
- **Недостаточно средств:** проверьте баланс и лимит API OpenAI. Подписка ChatGPT отдельно.
- **Бот не отвечает:** нажмите Start, проверьте токен, Chat ID и права бота в чате.
- **Ссылка не открывается:** откройте её в браузере и скопируйте прямой адрес ролика.
- **Нет сведений о видео:** заполните только отмеченные отсутствующие данные вручную.
- **Комментарий не появился:** прочитайте сообщение, проверьте сеть/ключ и попробуйте
  после устранения причины. Не запускайте новые платные запросы при неизвестном результате прежнего.
- **Видео уже обработано:** откройте сохранённую карточку в Моих заданиях вместо новой генерации.
- **Нет Интернета:** история и демо доступны; для реальных API дождитесь подключения.
- **Не удалось установить:** убедитесь, что установлен Python 3.12 с Python Launcher.
  Не отключайте TLS, проверку сертификатов или системную защиту ради установки.

Подробные решения доступны в разделе **Помощь**. Технические сведения остаются в
`logs/rubup.log`. Нужные сетевые узлы: `api.openai.com`, `api.telegram.org`,
`www.tiktok.com`, `tiktok.com`, `vt.tiktok.com`, `vm.tiktok.com`.
Текущая документация TikTok ранее блокировалась прокси среды разработки (403),
доступный публичный механизм автопубликации не подтверждён. Подробнее:
[docs/tiktok_api.md](docs/tiktok_api.md).

## Для разработчиков: команды и проверка

Команды необязательны для повседневного запуска:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe main.py --dry-run
.\.venv\Scripts\python.exe main.py --import-file .\videos.csv
.\.venv\Scripts\python.exe main.py --status
.\.venv\Scripts\python.exe main.py --prepare
.\.venv\Scripts\python.exe main.py --export .\history.csv
.\.venv\Scripts\python.exe -m pytest -q
```

CLI dry-run использует `data/dry_run.sqlite3`; рабочая база по умолчанию —
`data/history.sqlite3`. Тесты работают с временными базами и HTTP-моками, без реальных
публикаций, сообщений и платных запросов. Для Linux без дисплея установите
`QT_QPA_PLATFORM=offscreen`. Результаты текущего прогона: [docs/validation.md](docs/validation.md).
Обзор обновления: [docs/v2.md](docs/v2.md).

## Сборка Windows EXE и ZIP

Если нужен запуск без установленного Python, соберите EXE **на Windows** после
установки зависимостей:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_windows.ps1
```

Результат: `dist\RubUP-Automation\RubUP-Automation.exe`, без отдельной консоли.
Для передачи копируйте **всю** папку `dist\RubUP-Automation`, не один EXE.
Ключи, базы и оригиналы картинок не копируются сборщиком. Настройте их в мастере
при первом запуске. Сборка не подписана. Windows-сборка и её запуск здесь **не проверены**;
Linux не используется для заявления о готовом проверенном Windows EXE.

ZIP исходников собирается без окружения, ключей и пользовательских данных:

```powershell
.\.venv\Scripts\python.exe tools\package_project.py
```

Архив содержит исходники, тесты, установочные сценарии, документацию, доступные
скриншоты и `SHA256SUMS.txt`. Существующий архив заменяется только после успешной
проверки нового. `.env`, DPAPI-хранилище, базы, логи, пользовательские изображения
и вложенный ZIP из репозитория в него не включаются.
